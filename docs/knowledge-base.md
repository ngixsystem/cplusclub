# База знаний C+Club

Раздел `/knowledge` доступен из основной навигации всем четырём активным ролям. Материалы — общие технические справочники без данных клубов. Коллекция и отдельная статья проверяются `KnowledgePolicy`; отключённые пользователи не получают доступ. Членство клуба не требуется, поскольку раздел не читает записи клубов, оборудование, заявки или вложения.

## Содержание и границы

- 21 самостоятельная русская инструкция: назначение, шаги, проверка результата и источники.
- 371 запись каталога CCBoot в 17 тематических разделах. Все 370 ссылок из исходного оглавления сохранены; дополнительно найден старый недоступный адрес UEFI. Это каталог первоисточников, а не полный перевод 371 статьи. Оригинальные инструкции и скриншоты открываются у CCBoot.
- Поиск по полному тексту собственных инструкций и названиям/тематическим синонимам каталога; фильтры раздела и типа, избранное, постепенная загрузка карточек.
- Чек-листы и избранное сохраняются в localStorage отдельно по ID пользователя. Между браузерами не синхронизируются; при запрете хранения показывается предупреждение. Изменения не выполняют команды на оборудовании.
- Светлая/тёмная темы, мобильная компоновка, навигация клавиатурой, оглавление статьи и связанные материалы.

Проверка источников 2026-10-11 (UTC): 388 страниц wiki, включая 17 оглавлений; 620 уникальных HTTP(S)-ссылок. 9 ответов 404; ещё 21 случай без подтверждённой доступности/содержимого. Результаты: [отчёт ссылок](ccboot-link-audit.md). URL-алиасы нормализованы. Запрет автоматического доступа не равен неработающему сайту. Проверка HTTP не подтверждает техническую актуальность или безопасность скачиваемого файла.

Вся найденная HTML-документация обходится рекурсивно. Внешние ссылки проверяются без обхода других сайтов. Фрагменты-якоря, изображения и JavaScript-ссылки не проверяются. Полные исходные тексты остаются в игнорируемом `storage/app/knowledge-audit`, не публикуются и не коммитятся. В Git хранится только редакционный контент и метаданные аудита; подписи временных download URL скрыты. Старые рекомендации по ОС/защите не перенесены как универсальные действия.

## Обновление

Команды выполняются в Docker из корня проекта:

```sh
docker compose -f compose.test.yaml run --rm --no-deps python python scripts/audit_ccboot.py
docker compose -f compose.test.yaml run --rm --no-deps python python scripts/build_knowledge.py
```

Перед публикацией просмотреть изменения `ccboot-audit.json`, `library.json`, редакционные `guides.json` и отчёт. Новые руководства добавляются в `guides.json`; генератор проверяет доступность их источников. Страницы ничего не скачивают во время запросов пользователей и работают при недоступности CCBoot. Автоматического расписания обновления нет.

## Проверки и выпуск

Проверки выполняются в отдельном checkout на VDS (`/root/cplusclub-knowledge-check`) с отдельным Docker Compose project `cclub-kb-check`, PostgreSQL `cclub_test`, Redis и тестовыми аккаунтами. Нельзя запускать E2ESeeder или RefreshDatabase в production.

Подтверждены: TypeScript, production-сборка, 5 backend-тестов (764 assertions), 2 браузерных сценария. Проверены четыре роли, гость, отключённый аккаунт, неизвестный ID, полнота каталога, поиск, фильтры, пустое состояние, переход к источнику, сохранение избранного и чек-листа после перезагрузки, обе темы и ширина 390px. Снимки просмотрены вручную.

Миграций и новых зависимостей нет. При выпуске переносится проверенный код и собранные assets; конфигурация production, пользовательские данные и загрузки не меняются.
